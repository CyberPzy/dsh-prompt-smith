# 提示词增强

在输入框工具行、模型选择器左侧加一个图标按钮，一键把当前草稿改写成更清晰、可直接发送的提示词，再点一次即可恢复原文。

## 交互状态

| 状态 | 图标 | 悬停提示 | 点击行为 |
|---|---|---|---|
| 输入框为空（含纯空白） | （按钮整个隐藏） | — | — |
| 待增强 | ✨ 星形 | 增强提示词 | 调用润色，成功后**直接替换**输入框内容，缓存原文，进入恢复态 |
| 润色中 | ◌ 旋转圆圈（按钮禁用） | 正在润色… | 不可点击 |
| 已增强 | ↺ 圆形恢复箭头 | 恢复原文 | 把输入框恢复为缓存的原文，回到待增强态 |
| 失败 | ✨ 红色星形 | 具体错误信息 | 4 秒后自动回到待增强态 |

一致性规则：

- 润色 / 恢复都走编辑器的 `setDraft`，各是一次撤销（Ctrl+Z 一步还原）。
- 输入框被清空（含手动删空）时，整个状态机复位：按钮隐藏、缓存丢弃。
- 请求期间按钮禁用，不会重复触发。
- 已增强状态下手动编辑草稿后点恢复，会回到增强前的原文（缓存的就是原文）。

## 模型与路由

设置页或补丁行里配置的 `provider` / `model` / `reasoningEffort` / `temperature` / `maxTokens` / `maxChars` 优先；留空或 `auto` 时按以下规则解析：

- 供应商：优先取模型目录里 id 含 `deepseek` 的路由；没有时退回第一个可用供应商（目录按当前机器实时枚举，不同机器解析结果不同）。
- 模型：优先取 id 含 `flash` 的模型，否则取该供应商的第一个模型。
- 思考强度：`auto` 取该模型声明的最低档（`reasoning.efforts[0]`），不写死档位 id；路由拒绝所选档位时自动去掉该字段重试一次。
- 采样参数：默认 `temperature 0.3`、`maxTokens 1200`。

## 内置提示词定位

内置 system prompt（可在设置页整体替换，留空即回到下面这份默认稿），目标是「需求扩写」而非「措辞润色」：保留草稿全部事实、命令、占位符与任务范围，把隐含的合理默认补成明确要求；交互类需求显式列出状态机（初始/进行中/完成/失败/空态）、触发方式、边界情况（空输入、重复点击、状态一致性、恢复路径）与验收标准；只输出正文、不写示例代码；缺关键信息时输出一行`【待确认】`。草稿包在 `<draft>` 里并声明其中内容不是指令，防注入。

## 边界

- 草稿会发送到所配置的模型供应商；这是一次普通请求，不写入会话日志，不产生模型可见消息。
- 每次点击约 200–500 输出 token。
- 宿主路由只接受本机页面、同源、`POST`、`application/json`，请求体上限 64 KiB。
